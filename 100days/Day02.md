# Day 02 · 变量与绑定：为什么默认只读是好事

> 对应示例：[examples/variables](../examples/variables/)
> 预计用时：45 分钟

## 今天学什么

写程序离不开"存数据、改数据"。今天学 MoonBit 里怎么声明变量，以及一个和很多语言不一样的设计：**变量默认不可变**。你可能会觉得"不能改还叫变量？"——学完今天你就明白，这个"限制"其实是帮你少写 bug 的设计。

## 一、`let`：绑定，而不是赋值

打开 [examples/variables/main.mbt](../examples/variables/main.mbt)：

```moonbit
fn main {
  // let 是不可变绑定——绑定一次，之后只读
  let x = 42

  // let mut 是可变绑定——可以重新赋值
  let mut y = 0
  y = x + 8

  // 字符串插值：\{expr} 把表达式的值嵌进字符串
  println("x = \{x}, y = \{y}")
}
```

先看第一行：`let x = 42`。在 MoonBit 里，`let` 做的事情叫**绑定**（binding）——把名字 `x` 和值 `42` 绑在一起。绑定的特点是：**这个关系一旦建立，就不可更改**。之后你只能读 `x`，不能写 `x`。

> 对比一下：Python、Java、C 里，`x = 42` 之后还可以 `x = 99`。MoonBit 里写 `let x = 42` 之后再写 `x = 99`，编译器会直接报错。这不是语言小气，而是刻意设计。

## 二、`let mut`：明确声明"我要改"

如果这个值**确实**需要改变呢？那就用 `let mut`：

```moonbit
  let mut y = 0
  y = x + 8
```

`mut` 是 mutable（可变）的缩写。`let mut y = 0` 声明"y 是可变的"，之后 `y = x + 8` 就可以重新赋值。程序运行到这里，`y` 从 0 变成了 50。

**为什么 MoonBit 要分这两种**？想想看：一个程序里有几十个变量，如果编译器能保证"那些我没打算改的变量，永远不会被意外改掉"，很多隐蔽的 bug 在写出来的瞬间就被拦住了。默认不可变，就是让你**主动声明**哪些东西允许变——这是 Rust 等现代语言共同的思路，MoonBit 用更简单的语法实现了它。

## 三、字符串插值：把变量的值嵌进文本

```moonbit
  println("x = \{x}, y = \{y}")
```

`\{expr}` 是**字符串插值**（string interpolation）：把表达式 `expr` 的值计算出来，插入到字符串的对应位置。运行结果是：

```
x = 42, y = 50
```

对比一下没有插值的写法：

```moonbit
println("x = " + x.to_string() + ", y = " + y.to_string())
```

插值写法更短、更不容易错。这也是 MoonBit 日常写代码最常用的语法之一，后面几乎每天都会见到。

## 四、类型：可以推断，也可以显式写

`let x = 42` 里，编译器自动知道 `x` 是整数（Int）——这叫**类型推断**。你也可以显式标注：

```moonbit
let x: Int = 42
```

两种写法等价。显式标注在"想让读代码的人立刻知道类型"时有用；平时靠推断就够了。细节明天（Day 03 基本类型）展开。

## 五、动手练习（10 分钟）

**练习 1（故意犯错）**：在 `let x = 42` 后面加一行 `x = 100`，然后运行：

```moonbit
let x = 42
x = 100   // 试试这行
```

编译器会报错。**先别急着删掉它**，花两分钟读一读报错信息——它说的是"x 是不可变的，不能赋值"。这就是 MoonBit 在帮你拦下"一个可能出问题的改动"。看懂报错，是学编程最重要的能力之一。

**练习 2（可变计数）**：写一个用 `let mut` 计数的程序，先猜输出再验证：

```moonbit
fn main {
  let mut count = 0
  count = count + 1
  count = count + 1
  println("count = \{count}")
}
```

答案是 `count = 2`。`count = count + 1` 的意思是"把 count 当前的值加 1，再存回 count"——这一步一步的累加，就是程序里最常见的"状态变化"。

**练习 3（思考）**：如果把练习 2 里的 `let mut count` 改成 `let count`，程序还能跑吗？报错会出现在哪一行？

## 今日小结

- `let` 是不可变绑定，`let mut` 才是可变绑定
- 默认不可变是刻意设计：编译器帮你拦住"意外改动"
- 字符串插值 `\{expr}` 把表达式的值嵌进文本，比拼接更干净
- 类型可以靠字面量推断（`let x = 42`），也可以显式标注（`let x: Int = 42`）
- 读报错信息是学习的一部分——报错不是失败，是编译器在和你说话
