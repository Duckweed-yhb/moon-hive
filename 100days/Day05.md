# Day 05 · 控制流：让程序学会做选择

> 对应示例：[examples/control](../examples/control/)
> 预计用时：55 分钟

## 今天学什么

程序不能永远从上往下顺序执行。遇到条件要分支，重复的工作要循环。今天学 MoonBit 的控制流三件套：`if`、`match`、`while`。重点是一个和很多语言不同的设计：**`if` 和 `match` 是表达式，它们有值**，可以直接把分支结果赋给变量。理解这一点，写出来的代码会干净很多。

## 一、if：既是判断，也是表达式

打开 [examples/control/main.mbt](../examples/control/main.mbt)：

```moonbit
fn main {
  // if 是表达式：每个分支返回同一个类型的值
  let score = 85
  let grade = if score >= 90 {
    "A"
  } else if score >= 60 {
    "B"
  } else {
    "C"
  }
  println("score = \{score}, grade = \{grade}")
}
```

输出：

```
score = 85, grade = B
```

`score` 是 85，不满足 `>= 90`，满足 `>= 60`，所以 `grade` 是 "B"。

关键在写法：`let grade = if ... { "A" } else { "B" }`。**`if` 的整个结果直接赋给了 `grade`**，不需要先算好再单独赋值。这就是"if 是表达式"的意思：if 不是一个只做判断的动作，它本身产生一个值。

配套的规矩是：**每个分支必须返回同一个类型的值**。这里三个分支都是 String（"A" / "B" / "C"），类型统一，才能赋给 `grade`。如果一个分支返回 String、另一个返回 Int，编译器会报错，因为它没法确定 `grade` 是什么类型。

## 二、match：按值分支，必须穷尽

```moonbit
  // match 按值分支：必须覆盖所有情况，_ 是兜底
  let day = "Mon"
  let cn = match day {
    "Mon" => "周一"
    "Tue" => "周二"
    "Wed" => "周三"
    _ => "其他"
  }
  println("day = \{day}, 中文 = \{cn}")
```

输出：

```
day = Mon, 中文 = 周一
```

`match` 拿 `day` 的值和每个分支比较：`=>` 左边是模式，右边是结果。`day` 是 "Mon"，命中第一行，`cn` 得到 "周一"。

`match` 和 `if` 一样是表达式，有值。它的特别之处是**穷尽性检查**：编译器要求你的分支覆盖 `day` 所有可能的值。字符串理论上可以是任何内容，所以最后一行 `_ => "其他"` 是必需的兜底，`_` 表示"剩下的任何情况"。没有这个兜底，代码编译不过。这看起来是麻烦，其实是保护：以后往 `day` 里加一个新值（比如 "Thu"），编译器会提醒你 match 还没处理它，不会悄悄漏掉。

## 三、while：条件为真就重复

```moonbit
  // while 循环：条件满足就重复执行
  let mut i = 0
  let mut sum = 0
  while i < 5 {
    sum = sum + i
    i = i + 1
  }
  println("sum(0..<5) = \{sum}")
```

输出：

```
sum(0..<5) = 10
```

`while i < 5` 的意思是：只要 `i` 小于 5，就重复执行大括号里的两行。这个过程一步步走：

- 一开始 `i = 0`，`0 < 5` 成立，执行：`sum = 0 + 0`，`i` 变成 1
- `i = 1`，`1 < 5` 成立，执行：`sum = 0 + 1`，`i` 变成 2
- …一直加到 `i = 4` 时 `sum = 0+1+2+3+4 = 10`，然后 `i` 变成 5
- `i = 5`，`5 < 5` 不成立，循环结束

`<5` 表示不含 5，所以加的是 0 到 4。这个"从 0 加到 n-1"的模式在编程里非常常见。注意 `i` 和 `sum` 都要用 `let mut` 声明，因为它们在循环里被重新赋值（Day 02 讲过：只有 `let mut` 才允许改）。

## 四、动手练习（12 分钟）

**练习 1（动手）**：把 `score` 从 85 改成 92，重新运行。这次 `grade` 会变成什么？改成 59 呢？体会 `if` 分支是按从上到下的顺序逐个判断的。

**练习 2（故意犯错）**：把 `match` 里的 `_ => "其他"` 删掉，再运行。编译器会报错说 match 没有覆盖所有情况。读一读这段报错，它就是"穷尽性检查"在干活。把兜底加回去，错误消失。

**练习 3（思考）**：`while` 有没有可能一直不结束？把 `i = i + 1` 这行删掉再运行（先猜会发生什么，再试，注意按 Ctrl+C 终止）。这个练习不是让你害怕循环，而是让你知道：循环一定要有一个能变成假的条件，否则它会一直跑下去。

## 今日小结

- `if` 是表达式，有值，每个分支必须返回同一个类型
- `match` 是表达式，`=>` 左边模式右边结果，`_` 兜底，编译器强制穷尽
- `while` 条件为真就重复，配合 `let mut` 计数
- `sum(0..<5) = 10`：0 加到 4，`<5` 不含 5
- 循环里必须有能让条件变成假的变化，否则会死循环
